Union-facing OSS boundary for a qualified executable projection of the monotone-budget greedy attention allocation, grounded in Obsmetrologia mathematics.


## Source-preserving heterogeneous attention mode

The existing scalar budget/candidates contract remains unchanged. The same ActivityStreams Offer/Accept + capability + WitnessJournal border now also accepts mode **heterogeneous-frontier**: four explicit integer resource budgets (humanReentries, computeMillis, cashCents, wallMinutes), original source-qualified candidate claims, optional receiver/valuation, and optional requires/excludes references to other candidate IDs. No new queue, scheduler, or office is introduced.

A candidate without a valuation or receiving condition remains in intake/held, not dropped or assigned an invented score. Source-declared benefits are separately keyed by named receiving conditions, not combined into universal utility. Qualified candidates are tested against four independent resource budgets and their dependencies, yielding the conditional nondominated subsets plus deferred inputs. Up to 12 qualified candidates are enumerated exactly; larger sets request decomposition, and more than 128 nondominated alternatives causes an explicit frontier-too-wide response instead of an undisclosed truncation.

This is a *source-qualified comparison of projections*, not a proof of gain, psychological diagnosis, human cost measurement, irreversible physical entropy, permission to act, or independent receiver acceptance.

**Privacy/receiving gate:** the existing service contract and provider-local witness ledger carry request contents, including candidate claim strings. Do not route a person's private conversation or sensitive source text through this service until its owning controller has verified access controls, retention, permission and permitted provenance projections; source identifiers may be safer than reproducing private material, but still require disclosure review. This draft does not install automatic chat capture or claim such a privacy review occurred. All resource and benefit quantities must be provided and tested by the calling authorized office. Costs/benefits are assumed additive *only for this sequential conditional comparison*. There is intentionally **no Obsmetrologia theorem receipt** for this extension: the existing scalar Lean result does not establish multi-resource, receiver-indexed economics.

Scientific receiving: https://github.com/lenticule-science/science-services-section/issues/206 ; original generated-strategy and proof frontier: https://github.com/lenticule-science/obsmetrologia/pull/75 ; MetroPlat's eventual typed Leader decision/interrupt surface: https://github.com/red-cup-engineering/metroplat/issues/10 . ### Marginal budget sensitivity gauge

An optional `sensitivity: { resource: "computeMillis", increment: 50 }` asks how the **same** conditional Pareto frontier changes under a hypothetical 50-millisecond increase to the supplied compute budget. The returned `sensitivityGauge` reports baseline/expanded budgets, newly budget-feasible frontier selections and a separate exact-rational finite difference for each **named receiver condition**. A condition's envelope maximum and another condition's envelope maximum may require different, incompatible selections. All figures are customer-supplied projections, not measured results, generalized shadow prices, actual provider account headroom, grant or permission to spend. If the bounded baseline or expanded frontier is incomplete, the gauge refuses to infer marginal value. The original cash budget stays unchanged unless the caller explicitly asks for a purely hypothetical cash sensitivity; no request may authorize spending.
